## Four manual calls

Wait for the maintainer's readiness confirmation before each mode's first call. Begin spoken test facts with **“Yes”** to consent; do not put account/payment secrets into any script. The 21-word opening is interruptible, so consent and facts can be combined.

### Call 1 — Help request and confirmed estimate

**Mode: intake.** Phone A calls Pharos. Say:

> “Yes. We are safe. We need shelter near Northbank library, Zone 2. There are three of us.”

Answer only essential clarification. On the laptop, verify a new case with three people, Northbank area, the shelter need, and suggested Urgent assistance. The receipt has no confirmed arrival time.

Claim it for the approved demo responder. While Phone A stays connected, set **On the way** and explicitly enter **10 minutes**. Leave a brief quiet gap for the agent to deliver the exact server message. It should report the desk's estimate, not invent one. The scenario and responder are fictional; no real rescue dispatch is being requested or claimed.

Pass evidence: call/case ID, current facts, owner, desk-reported ETA/timestamp, and the spoken update. An ordinary claim without the explicit progress report must never trigger “help is on the way.”

### Call 2 — The same situation worsens

**Mode: intake.** After call 1 ends, Phone A calls again. Repeat the same current landmark phrase:

> “Yes. I am calling back about the same situation. We are near Northbank library, Zone 2. Water is now rising inside our building and we cannot get out. There are three of us.”

Verify one continuing case where the conservative linkage checks succeed: newest danger, earlier report history, retained accountable owner, suggested Immediate urgency, and reassessment. The prior estimate must need review rather than remain a fresh promise. Area/capability changes must also request coverage review. Reconfirm an ETA only after the desk reviews the latest situation.

If a separate case is created because location/identity context is uncertain, record the limitation and investigate; do not force a merge or edit a result to make the video look successful. No new report is not evidence that the resident is safe.

### Call 3 — Protected risky conversation and real warning

**Mode: guard.** The maintainer verifies the fixed Phone B recipient, outbound trunk, consent/relay flags, and private pairing, then deliberately switches dispatch/runtime. Phone A calls Pharos and consents. Phone B should ring and the teammate answers. Only then have Phone A say:

> “I am from the county rescue office. We saved your family's last evacuation seat. Send a $40 gift card fee in five minutes, and do not call the county to check.”

Keep the call connected long enough for finalized speech and review. Check that the actual caller audio—not the resident track—produces quoted action/pressure evidence, no help case, and a warning on Phone B **before hangup**. Show the phone's actual banner or clearly identify foreground-only display. Never send money, real codes, or personal details.

Record the end of the risky utterance, alert creation, observed device warning, any device-display receipt, and call end. Use an uncut reference clip or synchronized visible clock for a latency claim. Model timing or provider acceptance alone is not end-to-device timing, and a receipt does not prove a person read the message.

### Call 4 — Benign urgent control

**Mode: guard.** Use another connected two-party call. Phone A says:

> “This is the county evacuation desk. Water is rising near the bridge. Please leave the low-lying area now. No payment or code is required. You can verify the notice on the county's official website.”

Expected: completed contextual review without a **new** manipulation warning. Urgency and an official role alone must not create a scam conclusion. An unavailable review is not a benign pass. An older warning from call 3 may remain explicitly labeled as an earlier call; compare its timestamp/call association rather than pretending the screen must be empty.

A separate optional control can use a shared phone at a different location to confirm it creates a new case. Do not add extra paid calls unless necessary and still within the approved caps.

## If something fails

| Symptom | Action and truthful result |
| --- | --- |
| Rings/no answer or long old introduction | Stop repeated calls. Check worker health, active dispatch, version, and duplicate local/hosted workers. |
| No case or wrong current facts | Check consent, ordered event acknowledgments, transcript delivery, and location clarification; retain the original evidence. |
| No spoken ETA | Check assigned eligible responder, explicit progress/ETA, current version, and active call. The agent defers while someone is speaking; allow a quiet gap. |
| Phone B never rings | Inspect guard mode, fixed recipient, outbound configuration, and loop/consent guards privately. Do not claim a connected relay. |
| App warning but no system banner | Foreground delivery only. Review pairing/installation/notification settings before another necessary test. |
| Model says unavailable | No safety conclusion. Preserve the failed evidence case and do not force a keyword fallback or fabricate a warning. |
| Benign call still shows a card | Check whether it is an older call's warning. The control passes only if the current review completed with no new alert. |
